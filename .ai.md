## Non-Negotiable Invariants

1. **Continuous Doc API & OpenAPI Updates**: Both [`.ai/doc-api.md`](.ai/doc-api.md) and `api/openapi/openapi.yaml` (served via `/docs`, `/redoc`, `/api/docs`, `/openapi.json`) MUST be kept updated on **every code change or addition**, no matter how small the created or modified code is.
2. **Secured Logging**: All logging must be structured JSON (`log/slog`). Strictly redact JWT bearer tokens, `Authorization` headers, database DSNs/passwords, Redis credentials, and customer PII/PHI before emission. Raw `fmt.Print*` and `log.Print*` statements are prohibited in production code.
3. **Strict Vector Schema Immutability (ADR-001)**: Reject any in-place modification to `embedding_model`, `dimensions`, or `distance_metric` with `ErrStructuralMutationDisallowed`. All schema upgrades must transition through the Blue-Green migration state machine (`ACTIVE` -> `REINDEXING` -> `PROMOTED` / `ABORTED`; direct `REINDEXING` -> `ACTIVE` is disallowed).
4. **Replay Buffer & Zero-Lag Promotion Gate (ADR-002)**: While in `REINDEXING` state, ingestion routing policy is `DUAL_WRITE`. `PromoteIndexPointer` is strictly blocked until backfill completes and delta replay buffer lag (`kb_catalog_migration_delta_lag_records` / `kb_migration_delta_lag_records`) reaches `0`.
5. **Versioned Redis Keys Over In-Process L1 Invalidation (ADR-003)**: Standardize on direct Redis 7.2 Cluster reads ($P99 \le 5\text{ms}$ at 3,000 RPS) using monotonic version keys (`kb:{tenant_id}:{id}:v{version}`) co-located with `kb:{tenant_id}:{id}:latest_version` via `{tenant_id}` CRC16 hash tags and a bounded safety TTL (1 hour / `3600s`). Never use volatile in-process L1 caches or Pub/Sub invalidation buses.
6. **Optimistic Concurrency Control & PgBouncer Exec Mode (ADR-004)**: Configure `pgx/v5` with `default_query_exec_mode = exec` (`pgx.QueryExecModeExec`) to eliminate prepared statement incompatibilities with PgBouncer transaction pooling, and enforce monotonic integer `version` checks (`version = version + 1`) on all updates (returning HTTP `409 Conflict` / gRPC `Aborted` on mismatch).
7. **Transactional Outbox Delegated Exclusively to Debezium (ADR-005)**: Commit domain events (`KBCreated`, `KBUpdated`, `ReindexInitiated`, `PointerPromoted`, `ReindexAborted`, `KBDeleted`) atomically to the `outbox_events` table in the same PostgreSQL transaction as entity state changes. Run zero internal outbox polling loops.
8. **Strict Multi-Tenant Isolation**: Every PostgreSQL table and query must enforce explicit `tenant_id` scoping; repositories reject unscoped queries.
9. **Memory & Runtime Bounds**: Maintain flat Resident Set Size (RSS) $\le 128\text{MiB}$ per Go pod using `sync.Pool` buffers, deployed in a multi-stage distroless container (`gcr.io/distroless/static:nonroot`).
10. **Code Cleanliness**: All Go code must pass `gofmt -s`, `go vet ./...`, `golangci-lint run ./...`, and `go test -v -race ./...`.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features 
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

---

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Format and lint Go code: `gofmt -s -w .`, `go vet ./...`, and `golangci-lint run ./...`.
2. Verify hexagonal domain isolation: Ensure `internal/domain/` has zero third-party I/O imports.
3. Run test suites with race detection: `go test -v -race ./internal/... ./test/unit/... ./test/integration/... ./test/chaos/...`.
4. Verify [`.ai/doc-api.md`](.ai/doc-api.md) and `api/openapi/openapi.yaml` are updated with all API, RPC, schema, or storage modifications, no matter how small.
5. Verify Secured Logging rules: Ensure structured `log/slog` JSON logging is used and no raw tokens, secrets, DSNs, or PII are logged.
6. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
